# gpt-diet-fitness
Building a diet and fitness tracker that works for my brain around OpenAI APIs. This is a personal side project, so the format of the fitness and nutrition tracking is somewhat specific to how I see things, but I think the general state management pattern is flexible enough to be useful in other contexts. Or maybe not who knows! Also somebody let me know if this is already a thing. 

### Why though?
I spent a week or two trying to do this in ChatGPT, with some success, but I ran into a few problems:
 - GPT-5.2 is fairly reliable, but still would consistently make mistakes trying to preserve state solely through context. For example, I maintain a weekly checklist of workouts to do, and updating the list would sometimes uncheck other items that I would have to correct.
 - It's hard to maintain a mental model of where I'm at without constantly asking ChatGPT to reproduce the list, which exacerbated:
 - Chats very quickly becoming bogged down and "toxic". After about a week of tracking food Chrome would effectively crash when I tried to open that chat
 - Workarounds, such as managing state in other applications, require a painful amount of copy/pasting, oof
 - Overall, trying to use ChatGPT for this has been great for input and insight, but terrible for reliably managing state. It feels like trying to run through a pool full of maple syrup.

Perhaps trying to use ChatGPT to track complex state is kind of a misuse of the tool anyway. I tried using memory but it yelled at me.

### The very high level idea:

 - Store general information about the user as state objects
 - Store highly detailed information about the user's activity and diet history
 - Also store generated summaries and tables to show in the UI / dashboard
 - Send and update the appropriate state objects depending on the prompt the user is submitting. _For example_, a photo of a meal with a description of what it is, would:
   - Include general information about the user's diet and goals 
   - Include the appropriate state objects (what the user had already eaten, their recent physical activity)
   - Include instructions for how to handle that type of request, like how to update provided state objects
   - Trigger an event that the on response that updates the state objects (including summaries) with the updated nutritional information

### The _somewhat_ high level idea:
 - Detailed information about the user's goals, general activity level, dietary restrictions, and eating habits. Some of this information is generated via onboarding prompts. This information is sent with *every* query.

#### Interactions with GPT
 - General chat: pass _summary_ level context along with user prompt to ask questions
 - Add food: pass and update the daily eating state object
 - 'Complete' day of eating: create an extry in the larger running table state object
 - Log activity, or actively workout: pass weekly checklist as well as recent state. For example, similar to eating, a user might log different parts of a workout as it happens
 - 'Complete' activity: update the weekly checklist
 - 'Complete' week of activity: update the running checklist table. Another option: only use this object as the source of truth and derive the weekly checklist based on the latest row
